## 1. 使用者、问题与成功标准

面向维护 Python AI 应用的开发者和小型开发团队。用户上传项目的软件物料清单（Software Bill of Materials，SBOM），检查依赖及公开漏洞公告匹配，追踪间接依赖路径，比较升级候选，并通过 AI 获取带证据的解释。

主要使用流程：

1. 导入包含软件包版本和依赖关系的 SBOM，看到数据完整性和公告查询状态。
2. 选择一条公告匹配，看到项目到受影响包实例的路径，以及公告的来源和版本范围。
3. 查看同一受影响包在其他已导入项目中的出现情况，每个项目保持自己的依赖上下文。
4. 选择一个已经导入的候选快照，比较依赖、公告匹配和检查结果的变化。
5. 提问“通过哪个依赖引入？”或“这个候选有什么变化？”，得到与图查询及原公告一致的回答。

完成标准是可运行的产品、可追溯的真实数据、可复现的实验与明确标注的局限。招聘效果、实际事故减少和客户价值尚没有实证，不作为已取得成果。业务价值通过后续真实开发者反馈验证；没有反馈时，只报告技术和任务评估结果。

## 2. v1 范围与交付物

### 必须交付

- Python／PyPI 软件包身份归一、CycloneDX 1.6 JSON 导入、deps.dev 公开依赖图导入。
- Neo4j 中按快照保存的依赖实例图，以及 OSV 查询、公告版本、别名和匹配证据。

- 数据质量报告、独立评估集、实验报告、成本记录、双语使用说明和演示材料。
- 容器化启动、持久化数据、健康检查、自动化测试和一份独立 Git 仓库。

### 范围边界

v1 是单用户、本地或自托管应用；不提供多租户、企业登录、漏洞利用、源代码可达性分析或自动修改外部仓库。公开元数据分析和实际项目环境检查分别标明来源。实时攻击概率预测没有标签支持，不纳入本次项目。

前端主要使用英语，AI 支持中英文问题，项目文档提供中英文版本。模型缺失或 API 不可用时，图谱和数据分析功能仍可使用，问答页显示不可用原因，不能用预制答案冒充模型生成。

## 4. 数据契约、身份与来源

### 导入契约

- 上传接受 CycloneDX 1.6 JSON，并使用保存的官方 JSON Schema 校验；其他格式返回明确的版本／格式错误。
- 单次上限为 10 MiB、10,000 个组件实例、50,000 条依赖边；超限不截断导入，返回限制和实际数量。
- 包括 metadata.component 在内的 bom-ref 必须唯一。重复标识、悬空引用或相互冲突的包坐标拒绝发布快照，并返回 JSON 字段位置。
- 缺少包版本、未识别生态或没有可靠身份的组件可作为 opaque 实例保存，不能查询成“无漏洞”。
- components 中没有对应 dependencies 条目的组件标为依赖未知；明确的 dependsOn 空数组代表来源声称无进一步依赖。两者在界面、计算及导出中区分。
- 支持嵌套组件，保留 BOM 根与组件关系；循环依赖允许保存，遍历必须终止。没有可确认的根时只显示库存与局部关系，不给出项目根路径。

### 身份规则

PyPI 名称按 PEP 503 归一：小写，并将连续的 `-`、`_`、`.` 替换为单个 `-`。版本保留原字符串，同时用 PEP 440 解析可比较表示；解析失败的版本保留为未知，不猜测版本范围。PURL、name 和 version 的可靠字段相互冲突时不自动选取其中一个。

全局 PackageVersion 由生态、归一名称和可确认的版本标识组成；组件实例由 snapshot_id 与来源局部标识组成。deps.dev 节点使用返回数组的索引作为局部身份，不能把同版本的多个解析实例合并。

### 不可变快照

同项目、同来源原始文件 SHA-256 的重复导入返回已有导入结果，不增加节点或边。原文件、来源 URI、获取时间、内容校验值、schema／解析器版本必须保留。快照发布后依赖图不可变；公告刷新产生新的 MatchRun，保留旧的查询和公告版本。

每个快照有独立根、来源类型、声明的环境信息和图完整性状态。deps.dev 的通用 Linux 解析语境不能替换用户上传 SBOM 的操作系统、Python 版本或 extras。声明不完整时记为 unknown，不能自行补全。公开源请求由包坐标构造固定官方端点，不跟随上传文件中的外部 URL，也不从 SBOM 指定的地址抓取资料。

## 5. Neo4j 数据模型

采用 Neo4j Community 5.26 LTS 系列；实际镜像补丁和摘要在首次成功集成时记录并固定。核心功能不依赖 Enterprise、APOC 或付费图算法插件。

| 节点 | 身份与职责 |
|---|---|
| Project | 用户创建的项目；可含用户声明的用途和重要性 |
| Snapshot | 项目下的一次不可变导入；保存根、来源、完整性和环境声明 |
| ComponentInstance | 快照内的组件／依赖实例；保存原始坐标及解析状态 |
| PackageVersion | 跨项目共享的可靠包版本身份，不保存跨上下文依赖边 |
| MatchRun | 一次公告查询运行；保存日期、来源覆盖与失败信息 |
| Comparison | 一次快照比较；固定基线与候选、两个 MatchRun、同批资料标识及验证记录 |
| Finding | 某运行中某组件实例的公告匹配组；不是已证实的可利用性结论 |
| AdvisoryRevision | OSV 记录的一次内容版本，由 ID、modified、内容校验值识别 |
| Identifier | 公告自身标识及其 aliases，例如 GHSA／CVE／PYSEC |
| EvidenceChunk | 可检索证据片段，关联原记录、JSON 指针或文本位置和模型索引版本 |
| Job | 导入／刷新／索引任务的状态与重试记录 |

关系：Project—HAS_SNAPSHOT→Snapshot—CONTAINS→ComponentInstance；Snapshot—HAS_ROOT→ComponentInstance；ComponentInstance—INSTANCE_OF→PackageVersion；ComponentInstance—DEPENDS_ON→ComponentInstance；MatchRun—FOR_SNAPSHOT→Snapshot；MatchRun—HAS_FINDING→Finding—FOR_INSTANCE→ComponentInstance；Finding—SUPPORTED_BY→AdvisoryRevision—HAS_IDENTIFIER→Identifier；Comparison—BASELINE／CANDIDATE→Snapshot；Comparison—USES_RUN→MatchRun；EvidenceChunk—DERIVED_FROM→来源节点。

**图模型约束：**DEPENDS_ON 的两端必须属于同一快照，所有路径按 snapshot_id 过滤。跨项目查询只能匹配共同 PackageVersion／公告证据，再分别返回各自的路径；不能跨快照接续 DEPENDS_ON。索引和唯一约束覆盖节点身份以及项目、快照、运行的查询键。

界面显示的“受影响项目数”指当前选择的 MatchRun 中存在已知公告匹配的项目，不等同于可被实际攻击的项目数。

## 6. 公告查询、归一与状态

优先使用 OSV 的包名、生态、确切版本查询，不自行重写所有生态的漏洞范围判断。缓存按完整查询坐标和查询日期保存。querybatch 只返回 ID 和 modified，需要获取对应公告全文并处理分页。

处理步骤：

1. 选取身份可靠的 PyPI PackageVersion，分批查询；每批最多 100 个查询，并发上限 4。
2. 对有 next_page_token 的单项继续查询，保留分页状态。
3. 获取公告全文，保存原始响应和 AdvisoryRevision。
4. 检查公告是否已撤回、是否有相应生态和包名；发生来源矛盾时记为 conflict，保留证据，不自动确认。
5. 用记录 ID 及明确 aliases 构建本次运行内的别名分组；related 不作为同一漏洞合并依据。
6. Finding 按实例与本次别名组去重，同时保留所有来源记录。旧运行的别名组不因新资料而改写。

包查询状态为 matched、no_match、unqueried、partial、error 或 conflict。no_match 只表示完整查询没有返回匹配；partial、error 和 unqueried 都不能计入“已查且没有匹配”的分母。撤回公告单独展示，不计入当前有效匹配。图结构完整性与公告查询覆盖分别报告，不合并成一个可以隐藏未知项的分数。

用户可选择历史 MatchRun；默认展示每个快照最近一次完成的运行，部分失败的运行必须显示覆盖情况。跨项目结果固定一份快照到运行的映射，并显示各运行日期；不能以某一项目的运行时间代表所有项目。

来源失败采用有界重试，响应 429 时优先遵守 Retry-After；其他可重试失败等待 2、4、8 秒，之后记录失败。HTTP 单次超时 20 秒，任务有总进度和取消入口。默认按用户点击刷新运行，不创建 Codex 定时任务。

## 7. 图分析与升级比较

### 影响路径

在已校验上限内，按快照加载完整邻接关系，用有 visited 集合的广度优先搜索计算可达组件、最短路径和反向影响范围。数据库负责持久化、条件筛选与证据关联，应用层有界遍历避免枚举全部路径。每个结果最多展示 20 条代表路径和 200 个图节点，显示“视图已收起”的数量；聚合计数不依据缩略视图计算。

图结构有未知依赖或来源解析错误时，结果标为已观察范围，不能声称不存在其他路径。根缺失时不能把任意孤立组件当作项目根。

### 升级比较

v1 接受两个已经导入的快照作为基线与候选。按可信包身份比较新增／移除／版本变化，并在同一次查询资料范围中比较公告匹配变化。比较任务对两个快照的包版本并集采集一次资料，两个 MatchRun 共享 collection_id 及公告版本清单。公告资料日期不一致、查询失败或依赖不完整时，报告比较限制，不能将未知项计为已消除。Comparison 固定上述输入，不能随后台刷新改变历史结果。

结果分为三个证据等级：

- metadata_comparison：公开解析图之间的差异；不代表用户项目能够安装。
- resolution_verified：存在相同目标环境声明的完整解析产物，且已经对有声明约束的边逐项校验；没有约束字段的边保持 unknown。
- tests_verified：除解析证据外，还保存该项目在候选环境中的测试命令、退出码、时间和结果校验信息。

上传 SBOM 本身不证明版本约束满足或测试通过。deps.dev 的版本约束仅在其来源上下文内校验，不能替代用户项目的约束。系统不自动安装未知项目依赖或执行上传文件中的命令；测试记录由明确配置的本项目／示例项目验证流程产生。

### 分析输出

提供组件实例数与唯一包版本数、直接／间接依赖、公告匹配组、跨项目共享依赖以及完整性统计。每个指标说明分母、运行时间和来源范围。候选方案可按“消除的已知匹配数、涉及项目数、声明的变更成本”排序；只有用户明确给出成本和项目权重时才启用加权排序。没有标签时不计算攻击概率或实际风险下降百分比。

## 8. AI、检索与费用

### 模型适配与运行配置

生成优先使用用户已有 DeepSeek API。默认官方端点为 `https://api.deepseek.com`，模型为官方文档当前列出的 `deepseek-flash`；使用非思考模式、最多 1,024 个输出 token。上线前通过用户自己的凭据实际验证可用模型并记录返回模型标识，默认别名的后端版本变化须进入实验清单。用户使用第三方服务地址时单独配置并执行契约测试，不能套用官方价格。

提供独立 GenerationProvider 与 EmbeddingProvider 接口，端点、服务商、模型名称、上下文限制及计价信息由本地配置指定；不把密钥写入仓库、日志或评估样本。GPT 的具体服务地址和模型尚未提供，因此本规格不预先声称 GPT 接口已经可用，也不自动将失败调用转到其他付费服务。

适配器必须通过实际调用契约测试，不能只凭“兼容”说明声称可用。首版向量服务采用本地 Ollama qwen3-embedding:0.6b，生成使用 API；仍提供向量 API 的可替换接口。实际模型标识／摘要、向量维度和文本处理版本写入索引清单。模型或维度改变时建立新的索引版本，不混用旧向量。

GenerationProvider 输入结构化消息和输出长度上限，返回正文、模型标识、用量以及供应商请求标识（若提供）。EmbeddingProvider 输入文本数组，返回逐项向量和用量。供应商缺少某项用量时写 unavailable，不按零处理。

### 检索契约

证据语料包含公告片段、包坐标、单条已记录依赖关系、查询状态和快照比较结果。每个片段有稳定 evidence_id 和来源定位；同一文件的切分最大为 2,000 个 Unicode 字符，重叠 200 字符，字段边界优先。向量返回维度必须与当前索引清单一致。

全文检索、向量检索和 Reciprocal Rank Fusion 混合检索使用同一原始证据集合。GraphRAG 在种子检索后，按选定快照的已记录关系寻找补充证据。所有方法最终最多使用 10 个片段、12,000 字符；顺序、去重和截断策略固定，并记录实际送入模型的 evidence_id。

项目范围来自界面选项或经过确认的实体坐标。存在多个同名项目或多个公告运行时，助手先要求明确范围。模型可以建议受限的调查意图，但参数需经过类型校验；计数和路径来自只读预定义查询，不执行模型生成的任意 Cypher。

### 回答契约

回答返回正文、结构化事实、引用 evidence_id、已使用的工具结果以及 limitations。每项涉及版本、数量、路径和升级变化的事实必须能关联证据；无法形成可靠证据的事实不作为确定结论输出。检索文本只用于证据，不能改变工具权限或操作指令。

输出引用首先验证存在且确实在本次上下文中；这只能保证引用可定位，不能保证语义支持。证据支持与回答正确性仍需单独评估。模型失败、解析失败或证据不足分别报告，不能归为正常空结果。AI 不自动变更项目或依赖。

### 费用与限额

费用记录区分供应商账单与依据公开单价、实际用量计算的估算值。单价须记录服务、模型、币种、适用日期和缓存计费条件；不具备可信计价信息时显示 unavailable。2026-10-13 核验的 DeepSeek 官方页面存在高峰／低峰和缓存差别；初始费用预留采用其 Flash 高峰单价上界，缓存输入 $0.006、未缓存输入 $0.30、输出 $1.20／百万 token。实际运行前重新核验单价，费用报告标明采用的计价规则，不能把上界估算当作真实账单。

每次批量 AI 实验必须在运行配置中声明金额上限和调用数上限，启动前显示预计规模；上限未设置时批量实验不启动。依据请求的输入及最大输出预留费用，再允许调用；预留可能触及上限时暂停并保留断点。交互问答初始会话上限为 20 次生成调用，进一步调用需用户在应用内提高限额。

金额上限由用户配置，没有默认为无限的付费任务；实际收费由供应商规则决定。超时或无法确认用量的调用保留费用预留，不自动释放为零费用；任何重试也占用调用和费用限额。修改模型、提示、检索或计价表都会产生新的实验配置版本。

## 9. 组件架构、界面与接口

### 架构

- React＋TypeScript＋Vite：前端，Cytoscape.js 展示有界依赖子图，发布构建使用 Node 22 容器。
- Python 3.11＋FastAPI：输入校验、服务接口、任务执行、图分析和模型适配。
- Neo4j Community：项目、快照、依赖实例、查询运行、证据与全文／向量索引。
- 内容寻址文件目录：保存原始资料、导出和实验记录，SHA-256 校验；由后端访问。
- 单个有界后台工作队列：导入、公开资料刷新和索引。Job 在数据库持久化，一次执行一个修改任务，读取接口可继续使用已发布快照。

模块包括 ingest、identity、sources、graph、analysis、retrieval、generation、evaluation 和 api。模块通过类型化数据对象／接口通信，原始来源与业务对象分开。v1 不引入 Redis、Kafka、多 Agent 或独立微服务。

### 页面与行为

1. 项目页：最近快照、查询日期、导入进度、数据未知项与公告匹配概要。
2. 依赖页：搜索包版本、展开邻居、显示路径和来源；默认收起大图。
3. 影响页：按公告查看当前项目路径及其他项目的独立路径。
4. 比较页：选择基线与候选、展示组件与公告差异、显示验证等级。
5. AI 页：选定项目／运行，提问后显示回答、证据和实际查询路径。
6. 实验页：查看运行配置、方法比较、问题级结果、用量及局限。

状态说明放在相应结果处，不在普通业务流程展示数据库实现细节。

### 接口职责

`POST /api/projects` 创建本地项目；`POST /api/projects/{id}/imports` 导入 SBOM；`POST /api/projects/{id}/public-resolutions` 请求预定义公开源解析；`GET /api/jobs/{id}` 读取进度；`POST /api/snapshots/{id}/match-runs` 刷新公告；`GET /api/snapshots/{id}/graph` 读取有界图；`GET /api/match-runs/{id}/findings` 读取匹配；`GET /api/findings/{id}/paths` 读取影响路径；`POST /api/comparisons` 比较快照；`POST /api/investigations` 调查问答；`GET /api/experiments/{id}` 读取评估结果。

写任务返回 job_id，读取结果带 snapshot_id、match_run_id（如适用）、observed_at 和 completeness。分页列表返回 next_cursor，界面与问答均不得将第一页当作全部结果。

## 10. 错误处理、运行与复现

导入状态为 queued、validating、fetching、writing、ready、failed、cancelled。分批写入未发布快照，直到结构校验通过才设 ready。失败及取消仅清理该任务拥有的未发布数据，已发布快照继续可读。重启后未完成任务标为 interrupted，可幂等重试。

错误响应包含稳定错误码、具体字段／阶段和是否可重试，不包含密钥或供应商完整认证响应。日志记录任务、来源、模型、耗时和失败类别；导出数据默认排除用户上传资料中的联系信息等非分析字段。

Docker Compose 启动后端、前端和 Neo4j，服务端口默认只绑定本机，持久化图数据库与证据文件。提供 .env.example，无真实凭据。健康检查区分进程可用、数据库可用、来源可访问和模型可用，不以模型故障阻断已有图谱浏览。

依赖版本及容器摘要在通过首次集成后锁定；交付必须有清洁环境复现记录、迁移版本和源资料清单。数据刷新不覆盖已发布实验使用的快照。定期导出数据库及证据校验索引的操作写在使用说明中，不建立外部定时自动化。

## 11. 评估设计

### 正确性验证

核心验证包括：重复导入、同版本不同实例、跨快照路径污染、缺失根、未知依赖、循环、悬空引用、版本冲突、公告分页、撤回、别名重复、来源失败和两快照比较。图路径结果与独立参考遍历核对；公告包／版本匹配用原始请求及响应复查。

### 固定问题集

建立 200 道问题，分为 60 道开发题、140 道冻结测试题：

| 类型 | 开发题 | 测试题 | 合计 |
|---|---:|---:|---:|
| 单公告与版本事实 | 12 | 28 | 40 |
| 依赖路径 | 18 | 42 | 60 |
| 跨项目影响 | 12 | 28 | 40 |
| 快照比较与升级证据 | 12 | 28 | 40 |
| 缺失、歧义及无可确认答案 | 6 | 14 | 20 |
| 合计 | 60 | 140 | 200 |

依赖于同一根包家族的所有案例归入同一集合；LangChain 系列与 LangGraph、LangSmith 的 family_name 固定为 langchain_family，其余根包各为一组，family_name 为其归一包名。将这 10 个家族按 `SHA256("20261013:" + family_name)` 排序，前三组用于开发题、其余用于测试题；缺少某家族的完整资料时保留该分配并登记覆盖损失。跨项目题的所有项目必须属于该题所在集合。DepScope 和新建示例应用的实际 SBOM 只用于功能验证，不用于补足公开语料题数。下游包和公开公告可以在两个集合出现，因此该评估衡量新调查场景表现，不声称识别未见过的漏洞。

原始证据语料包含测试题涉及的资料，这是检索任务所需；测试题和标准答案不能用于调参。同义重复问题及完全相同的标准证据组合需检查并去重。题目需有 source_ids、expected_facts、required_evidence 和 label_origin，参考标签由独立程序和来源逐项产生，记录作者审核状态。未经真实人工审核的标签标为程序参考标签，不能称为人工金标准。

### 方法比较

比较全文、向量、混合检索、混合加图谱遍历四种方法。固定同一语料、切分、生成模型、提示、生成参数和证据预算；精确包／公告标识的直接定位策略对四种方法一致。图谱方法的增益属于关系遍历补充证据的贡献，不能解释为图数据库普遍优于关系数据库。

指标包括 required_evidence 覆盖率、Evidence Recall@10、结构化事实准确率、引用可定位率、引用支持率、缺失／歧义题处理正确率、延迟中位数／P95、生成失败率、token 用量与费用估算。开放解释的语义支持以有记录的审核样本报告，自动字段匹配仅用于能确定比较的事实；模型评分不是唯一标准。

按题型报告结果和逐题差值。差值区间采用固定 seed=20261013、1,000 次按案例家族重采样的 bootstrap；独立组较少时明确其不稳定性。延迟报告模型、硬件／服务、并发、冷启动处理和实际输入输出规模，不与其他机器的结果直接比较。

测试集及配置在首次最终评估前保存校验值。测试后发现错误可修正真实软件缺陷，但必须登记修复及复评；不依据测试成绩选择提示或检索参数。若开展新优化，使用开发题并建立新的最终评估版本，不把反复使用的测试题描述为未见数据。

## 13. 实施顺序与外部输入

实施计划按“数据契约与导入 → 图谱和公告匹配 → 分析及比较 → 产品界面 → AI 与实验 → 部署复现及项目展示”的依赖顺序展开；这是阶段关系，不是本文件中的代码任务清单。

外部输入为用户 DeepSeek API 的本地凭据配置和批量实验费用上限；若使用第三方地址或备用 GPT 服务，再提供相应端点和模型配置。密钥只在本地配置，不通过聊天提供。Docker 服务需在开发环境准备阶段检查并启动。缺少 API 时可以继续非模型功能，但真实 AI 验收及相关实验不能宣称完成。
