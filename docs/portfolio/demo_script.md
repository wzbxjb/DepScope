# Five-minute real product demo / 五分钟演示

Use the actual local/container UI; the recorded `artifacts/verification/product-demo.webm` is a real browser workflow, not a mockup.

1. **Problem, 30s.** “A dependency list does not explain how an indirect component reaches an app or what evidence an upgrade recommendation relies on. DepScope keeps instances, versions, dates and unknowns explicit.”
2. **Graph/source, 60s.** Load the verified public LangChain sample. Explain the source kind/date, whole-inventory counts versus bounded visual view. Open advisory matches, select a real record, show its source and recorded impact path. A match does not establish exploitability.
3. **Own environment, 60s.** Create a project and import the actual backend SBOM. Repeat it to show idempotency, then import the independent example environment. Compare them as metadata evidence. Explicitly say these are different observed application inventories, not a tested upgrade.
4. **AI/evidence, 60s.** Select an explicit snapshot/query and ask for its recorded instance count. This step costs a real API call and requires configured embeddings/limits. Open the original source field and show usage/receipt. Explain that unsupported outputs are withheld and generated explanations are unverified.
5. **Experiment, 60s.** Open the real 800-call run. Show the 60/140 split and type-specific denominators. Hybrid test accuracy is 50/126; graph expansion is 48/126. Discuss the failed graph improvement and fixed context budget rather than claiming an uplift.
6. **Engineering/reliability, 30s.** Show source hashes, bounded tasks, persisted cost ledger and the actual new-instance restore report. State that this is a local portfolio project, without customer/ROI claims.

For an offline/no-key demo, use recorded source/evaluation artifacts and core graph features. Label live generation unavailable instead of substituting a fabricated answer. Never display `.env` or the private backup/signing key.
